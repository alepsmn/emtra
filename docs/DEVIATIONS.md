# Changes with respect to the H3 design

Running log of every point where the prototype departs from, or makes precise, the design delivered in H3. Written in English so each row can be pasted into the technical document. Add a row whenever a contract or a design decision changes (rule 1 of AGENTS.md).

| # | H3 reference | H3 said | Prototype does | Reason |
|---|---|---|---|---|
| 1 | §5.11, Table 50; §5.8 step 1 | Simulator fitted to the arrival records captured from the EMT API; F4 and F12 measured on recorded data | Fully synthetic corridor defined in configuration; no real data in the prototype (ADR 0001) | Every measure needs a ground truth to be compared with, which only the simulator provides; the course accepts coherent synthetic data |
| 2 | D6, Tables 43–45 | GCS for raw data, BigQuery + dbt as warehouse, Airflow for batch jobs | Local directory with the same partition layout, DuckDB + dbt-duckdb, jobs launched with `make` (ADR 0002) | No managed services needed to demonstrate the design; switching back is a change of dbt adapter and path |
| 3 | §5.5 | Edge, fog and cloud as containers on one virtual machine | Infrastructure (Mosquitto, TimescaleDB, Grafana, Kafka) in Docker Compose on a laptop; EMTRA services as Python processes | Simpler to run and record; tier boundaries are unchanged (the fog reaches the cloud only through the bridge) |
| 4 | FR03, Ingestor | GTFS timetable loaded daily; incidents, events and weather feeds | Timetable generated from the corridor configuration; context feeds not implemented | Follows from 1; context feeds only serve F5 and F7, which stay as design |
| 5 | D10 | Polling of the per-stop API in the prototype | `DataSource` interface with file and MQTT implementations fed by the simulator; the live EMT source is designed, not implemented | Follows from 1; the interface that makes the source replaceable is kept |
| 6 | Annex B.1 | Band closing not specified | The Ingestor publishes a watermark (minimum last poll time over the stops); the ReliabilityMonitor closes a band when the watermark passes its end plus an allowed lateness | With event time, a band with no arrivals would never close and a blocked segment could not be detected |
| 7 | §3.3 | c_vh defined per stop | Headways of all stops of the segment are pooled in each band; sample standard deviation (n − 1) | One stop yields about two headways per band at 6–8 min headways: too noisy to classify |
| 8 | Table 12 | Level-of-service limits with gaps between classes (0.30 / 0.31) | Upper limits are inclusive up to B and exclusive from C: A ≤ 0.21, B ≤ 0.30, C < 0.40, D < 0.53, E < 0.75 | Removes the ambiguity for values between two printed limits |
| 9 | Table 47 | "Action required" when the forecast deviation exceeds the action threshold | "Action required" when the band is outside the range and a detector signals, or the segment is blocked | No deviation forecast exists in the core increment; the rule uses what is measured |
| 10 | §5.8 step 4 | The disturbance is given to the simulator explicitly (e.g. the broken-down bus removed at t0) | The disturbance is implicit in the corridor state sent with the request (bus positions and gaps); an ongoing slowdown is not known to the planner | The fog does not know the cause of an alert, only what it observes |
| 11 | §5.8 | Evaluation model fitted independently of the observed world | The ActionPlanner evaluates with the same model that generates the simulated world | Follows from 1. Declared limitation: measured damping is optimistic |
| 12 | D5, [8] | Daganzo's headway-based holding as fallback | Simplified forward-headway rule: hold = clip(α·(H − h), 0, hold_max) at a control point | Smallest rule that keeps the idea; parameters in configuration |
| 13 | Table 41 | ActionPlanner ranks hold, short-turn, reinforce, detour and no action | Only hold and no action are evaluated | As planned in §5.11; the rest stays as design |
| 14 | Messages (Annex C.3) | Message identifier unspecified | Deterministic identifier (UUIDv5 of schema and natural key) | Consumers deduplicate after restarts and replays without extra state |
| 15 | Recommendation message | Every candidate carries simulated effects | A fallback recommendation carries candidates without simulated measures, flagged `fallback` | The fallback rule does not simulate |
| 16 | FR17, ConfigurationManager | Configuration changed by the operator and applied without restart | Configuration in versioned YAML files read at start | Designed, not implemented |
| 17 | §6.2 | "nine non-functional requirements" | Table 38 lists two | Inconsistency in H3 to correct in the text |
| 18 | §5.11, Table 50 | Increment 1 at H3, increment 2 at H4 | Increment 1 (F1, F3, F9, F6) delivered at H4; increment 2 (F10, F11, F4, F12) at H5 | Milestones shifted by one |
| 19 | Annex C (FogStore) | Arrivals stored with a unique message identifier | Unique on (message identifier, arrival time) | A TimescaleDB hypertable requires the partition column in every unique index; the arrival time is a function of the identifier's natural key, so duplicates are still rejected |
| 20 | Simulator | Scheduled arrival downstream = departure + sum of link means + dwell mean | The timetable keeps constant nominals (`link_mean_s` = mean of the 11 per-link means, `dwell_mean_s`); the simulated links differ per link | Keeps the WP1 timetable contract (constant step) and the schedule is only used for headways and band groups |
| 21 | Simulator | Link time CV 0.20 (0.30 in peak) | CV 0.25 in the peaks, 0.20 elsewhere | With 0.30 the clean-day mean c_vh of line 19 in am_peak exceeded the acceptance range for several seeds; parameter tuned, test untouched |
| 22 | Simulator | `blocked_segment`: no bus leaves the segment; `breakdown`: bus retired | A blocked segment holds departures from each line's last served stop in the segment (at the terminal the bus holds its bay); a breakdown removes the bus on arrival at a stop (default: first control point the line serves, before its terminal) and returns it after the duration, or never; `faults.parquet` holds the real firing times for `breakdown` and `dispatch_delay` | Smallest implementation of the catalogue that gives an observable effect |
| 23 | Annex C (FogStore) | Estimates stored as received | Unique on (stop, line, bus, poll time), inserted with `ON CONFLICT DO NOTHING` (migration `005_estimates_unique.sql`) | At-least-once delivery (QoS 1) can redeliver a snapshot after a restart; the unique index makes the insert idempotent, as for arrivals. The poll time is the hypertable partition column, as in row 19 |
| 24 | §3.3, Table 12 | On-time performance: share of arrivals with 0 ≤ delay ≤ 5 min | On time if −60 s ≤ delay ≤ 300 s (`otp_early_tolerance_s` in configuration) | With the literal definition any arrival ahead of schedule, even by 2 s, is late: in the synthetic corridor, where deviations are centred on the schedule, about half of the arrivals of a clean day were not on time and the LF level of service was permanently F |
| 25 | KPIs, K8 | EWMA+CUSUM compared with Shewhart at the same false-alert rate | Shewhart's `z_max` is tuned like L and h, separately for c_vh and OTP cells: the smallest value whose in-control ARL0 (1 / P(z > z_max) on the baseline residuals of that indicator) reaches `arl0_target` (c_vh 5.08, OTP 7.25; it was 3.0). The Shewhart run is a second Monitor pass (`shewhart=True`) whose alarm is reported as trigger `ewma`; its files are `*_shewhart.parquet` (INTERFACES §8) | With 3.0 the chart would fire far more often than the other two, and recall at unequal false-alert rates is not comparable. Reusing the trigger name avoids changing the `emtra.alert` contract; the comparison never leaves the batch harness |
| 26 | KPIs, K1 | Share of emitted estimates that reach the register measured end to end | In batch K1 compares the estimates in the raw snapshot file with the rows of `estimates.parquet`; both are written in the same process, so it is 100 % by construction | The end-to-end loss (MQTT, fog store) is only observable with the stack running: it is measured in E5 (WP12) |
| 27 | KPIs K3; Ingestor | Never-fulfilled confirmed after `grace_s` | The Ingestor also requires `never_fulfilled_grace_polls` consecutive polls of the stop without the bus (a failed poll does not count). The value (10, with `grace_s` = (N − 1) polls = 270 s) is calibrated by `make baseline` on the clean calibration seeds 2000–2019: the smallest N that removes every reappearance, capped at 12. `INTERFACES.md` is not affected (configuration only) | A bus can leave a stop's list for several polls (up to 9 observed on clean days) and come back; without the poll count it was declared never fulfilled and tracked again |
| 28 | KPIs K3, K5; E2 | K3: never-fulfilled with a true arrival; K5: medium/high faults of segment-wide types, 4 seeds per cell | K3: false only if the bus really arrives at that stop no later than the last estimated arrival + 300 s; denominator: every never-fulfilled emitted in E1 and E2. K5, K6, K8: high-severity `slowdown` and `blocked_segment`, both segments, 10 validation seeds per combination (40 runs); the other severities and fault types are informative, reported as detection against the size of the true effect (worst change of true c_vh / OTP over the fault's segment and its neighbours, fault run minus same seed without fault, hour after t0). Targets unchanged | A bus that vanishes for the length of a fault and arrives much later is a correct never-fulfilled; the first K5 population (4 seeds per cell, two severities) was too small to tell types and segments apart |
| 29 | §5.9, INTERFACES §10 | One EWMA L, CUSUM h and Shewhart z_max for all cells; demo seed 51 | L, h and z_max are calibrated separately for c_vh cells and OTP cells, same `arl0_target` (`config/reliability.yaml` holds `{cvh, otp}`; the detector state of a tern is shared and the limit is chosen by the indicator of each band). The demo seed is 47 | The two indicators have different residual distributions (OTP skewness 3.3 against 1.1), so one limit was loose for c_vh and tight for OTP. With the new limits seed 51 no longer meets the WP5 selection criteria (no attributable action-required alert); 47 does, with the alert on line 19, segment 1 |
